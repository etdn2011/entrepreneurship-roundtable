# 四维诊断

## 一句话核心
一个项目做不做得起来，就四个维度：做什么产品、怎么让人知道、怎么交到用户手上、用户骂你什么——哪个维度最弱，项目的天花板就在哪。

## 底层逻辑

### 四个维度缺一不可
- **产品**：解决什么痛点？用户愿意付多少钱？成本结构是否成立？
- **流量**：用户从哪里知道你？获客成本多少？流量可持续吗？
- **交付**：怎么把服务/产品交到用户手上？流程能标准化吗？
- **瑕疵**：用户为什么不买？买了为什么不满意？负评里藏着什么？

### 诊断顺序
先看产品（方向对不对），再看流量（有人知道吗），再看交付（能搞定吗），最后看瑕疵（怎么改进）。

### 关键指标
- 产品：用户付费意愿 / 成本结构 / 复购率
- 流量：获客成本 / 转化率 / 流量来源稳定性
- 交付：交付周期 / 用户满意度 / 可规模化程度
- 瑕疵：负评率 / 负评主题分布 / 负评改进速度

## 操作步骤

### 第一步：拆产品
- 这个产品解决什么具体问题？
- 用户愿意付多少钱？成本多少钱？
- 毛利多少？能做起来吗？

### 第二步：拆流量
- 第一批用户从哪来？
- 获客成本是多少？获客渠道可持续吗？
- 有没有免费的流量来源？有没有付费的流量天花板？

### 第三步：拆交付
- 用户下单后，怎么把东西交到用户手上？
- 流程能标准化吗？能不能复制？
- 用户等多久？体验好吗？

### 第四步：拆瑕疵
- 用户不买的原因是什么？
- 买了不满意的原因是什么？
- 负评主题是什么？有哪些是产品问题、哪些是交付问题？
- **负评就是金矿——改掉一个高频负评，可能比做个新功能更有用**

## 什么情况下好用
- 项目遇到瓶颈，不知道问题出在哪
- 想系统性地诊断创业项目
- 产品上线后数据不好，想找到抓手

## 什么情况下别用 / 容易犯的错
- 别在需求还没验证时就做四维——先搞清楚有没有人需要，再拆细节
- 四个维度都要做，但优先级不同——先搞产品再搞流量，别倒着来
- 别只看数量不看质量——100个负评可能都是同一个问题
- 拆了不改等于白拆——四维不是分析工具，是行动清单

## 在圆桌中怎么聊这个角度

- **老齐**（方向判断）：先从产品入手——"先别想怎么卖，先搞清楚你的产品到底解决什么问题。用户凭什么要掏钱？"
- **方鸣**（验证方法）：系统性地拆——"把项目拆成四个环节：做什么、怎么让人知道、怎么交付、用户骂什么。哪一环最弱？"
- **沈锐**（落地执行）：给行动清单——"今天就做一个四维检查表，每个维度打一个分，最低分就是你要先解决的问题"
- **苏慎**（风险排查）：重视负评——"别只看好评。用户不买、买了不满意——这些信息才是你改进的方向。看看负评里有没有共性问题"
